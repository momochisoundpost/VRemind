# VRemind 1.1 UI Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver full-bleed creator avatar background and adaptive monochrome text contrast for the Small Hero desktop widget, along with a pointing hand cursor and full-handle tooltip for the menu bar popover.

**Architecture:** Use a backward-compatible WidgetKit container background extension and `@Environment(\.widgetRenderingMode)` detection in `SmallHeroWidgetView` to provide edge-to-edge avatar crops and high-contrast dark typography during desktop window focus. Use a lifecycle-safe `PointingHandCursorModifier` and SwiftUI `.help` tooltips in `ChannelRowView` without impacting the untouched Large Dashboard widget.

**Tech Stack:** Swift 5.10, SwiftUI, WidgetKit, AppKit, Swift Testing, Xcode Command Line Tools.

**Spec:** `docs/superpowers/specs/2026-11-12-vremind-1.1-ui-polish-design.md`

## Global Constraints

- macOS target floor is macOS 12.0 Monterey (`platforms: [.macOS(.v12)]`).
- Build strictly using Xcode Command Line Tools (`/Library/Developer/CommandLineTools`), zero full Xcode IDE dependencies.
- Zero third-party dependencies (pure Swift / AppKit / SwiftUI / WidgetKit).
- `LargeDashboardWidgetView.swift` must remain strictly untouched.
- All existing 163+ tests across 19 suites must continue passing via `bash scripts/test.sh`.

## Review Focus

1. **Monochrome desktop text contrast:** When `widgetRenderingMode == .accented` or `.vibrant`, `SmallHeroWidgetView` text colors must evaluate to `Color.black` rather than white.
2. **Missing avatar monogram contrast in monochrome mode:** When a creator has no avatar image on disk, the monogram letter and background must remain clearly legible under monochrome tinting.
3. **Cursor stack balance:** Moving the mouse into and out of a channel row or collapsing the popover must never leave lingering `NSCursor.pointingHand` instances pushed onto the cursor stack.
4. **Canonical handle formatting in tooltip:** Handles stored with or without a leading `@` must always display with a leading `@` in the tooltip.
5. **Widget container backward-compatibility:** The `widgetContainerBackground` helper must compile cleanly on macOS 12 and activate `.containerBackground(for: .widget)` on macOS 14+ without runtime faults.

- [ ] **Step 3: Implement cursor modifier and tooltip in `ChannelRowView.swift`**

1. Define `PointingHandCursorModifier`:
   ```swift
   struct PointingHandCursorModifier: ViewModifier {
       @State private var isHovering = false

       func body(content: Content) -> some View {
           content
               .onHover { hovering in
                   if hovering != isHovering {
                       isHovering = hovering
                       if hovering {
                           NSCursor.pointingHand.push()
                       } else {
                           NSCursor.pop()
                       }
                   }
               }
               .onDisappear {
                   if isHovering {
                       isHovering = false
                       NSCursor.pop()
                   }
               }
       }
   }

   extension View {
       func pointingHandCursor() -> some View {
           modifier(PointingHandCursorModifier())
       }
   }
   ```
2. Add `public var formattedHandle: String` to `ChannelRowView`:
   ```swift
   public var formattedHandle: String {
       channel.handle.hasPrefix("@") ? channel.handle : "@\(channel.handle)"
   }
   ```
3. Attach `.pointingHandCursor()` to the channel button and `.help(formattedHandle)` to `Text(channel.handle)` and the channel info stack.
