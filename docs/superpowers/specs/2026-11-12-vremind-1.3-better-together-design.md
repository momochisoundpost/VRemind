# VRemind 1.3 ("Better Together") Design Document

- **Status:** Complete (Ready for Approval)
- **Date:** 2026-11-12
- **Author:** Antigravity / Caitlyn Momochi
- **Target Version:** 1.3

---

## 1. Intent & The Why

VRemind started as a 100% native macOS menu bar utility for tracking VTuber YouTube livestreams without API keys or external dependencies. As the community around VRemind grew, two pressures emerged:

1. **Multi-platform creators:** Many VTubers stream on **Twitch** (and other platforms) in addition to—or instead of—YouTube. Tracking only YouTube misses live broadcasts on Twitch.
2. **Cross-platform portability without diluting the Mac app:** External contributors (such as KDE Plasma and GNOME developers) want to port VRemind's reminder capabilities to Linux desktops. VRemind itself will **always remain 100% native macOS** (`SwiftUI`, `AppKit`, `WidgetKit`, `UserNotifications`), but today's `VRemindKit` mixes pure business logic (`LivePageParser`, `WatchedChannel`, `CelebrationDetector`) with Apple-only frameworks (`AppKit`, `Combine`, `SwiftUI`, `UserNotifications`, `WidgetKit`).

**VRemind 1.3 ("Better Together")** solves both by splitting out a pure, platform-agnostic Swift core (**`VRemindCore`**), turning **`VRemindKit`** into the macOS bridge between `VRemindCore` and the native macOS UI/Widget targets, and introducing **Twitch** support alongside YouTube under a unified provider architecture.

---

## 2. Goals, Non-Goals, & Anti-Goals

### Goals
- **Core / Bridge Architecture Split:**
  - Extract **`VRemindCore`** as an independent SwiftPM library target importing **only `Foundation`** (plus `#if canImport(FoundationNetworking)` where HTTP types are used), containing all domain models, provider/parser logic, polling & deduplication rules, celebration detection, and persistence abstractions.
  - Refactor **`VRemindKit`** into the **macOS bridge** wrapping `VRemindCore` for `ObservableObject` state, `UserDefaults` persistence, `NSWorkspace` sleep/wake monitoring, `UNUserNotificationCenter`, `WidgetKit` snapshots, `UpdateService`, `LaunchAtLoginHelper`, and SwiftUI views.
  - Keep `VRemind` and `VRemindWidget` 100% native macOS apps.
- **Twitch Support (Zero API Keys):**
  - Add `TwitchStreamProvider` alongside `YouTubeStreamProvider` behind a shared `StreamProvider` protocol in `VRemindCore`.
  - Detect live status, stream title, stream ID, start timestamp, display name, and channel avatar for Twitch channels without requiring user-supplied API keys or OAuth tokens.
- **Separate Multi-Platform Watchlist & UI:**
  - Treat each `(platform, handle)` pair as an independent watchlist entry so a creator on both YouTube and Twitch can be tracked separately.
  - Add a **platform dropdown** on the left side of the add-channel input bar (`AddChannelBarView`) to pick between YouTube and Twitch.
  - Display a small **colored platform badge** at the bottom-right corner of each channel's circular avatar (YouTube: red; Twitch: purple).
  - Update click-through links, notifications, onboarding, and desktop widgets (`WidgetSnapshot` / `WidgetChannelItem`) to be platform-aware.
- **Seamless Upgrade from 1.2:**
  - Automatically migrate existing 1.2 `UserDefaults` watchlists and widget snapshots by defaulting legacy entries without a `platform` field to `.youtube`, preserving `lastNotifiedVideoId`, `lastNotifiedUpcomingId`, `lastStreamedAt`, `name`, and `avatarURL`.

### Non-Goals
- **Kick support:** Deferred beyond 1.3 due to Cloudflare bot protection on Kick's unauthenticated endpoints vs. OAuth credential requirements on Kick's official API.
- **RSS / podcast / article feeds:** Deferred to a later release (kept in mind via `StreamProvider` / `StreamPlatform` extensibility).
- **Linux GUI, KDE Plasmoid, GNOME extension, or CLI binary:** This repository remains macOS-focused; `VRemindCore` provides the portable Swift business engine and reference architecture for external porters.
- **Twitch upcoming schedules:** Twitch does not expose YouTube-style upcoming waiting rooms on channel pages; Twitch channels report `.live`, `.offline`, or `.unknown` (while `.upcoming` remains supported for YouTube and future providers).

### Anti-Goals
- **Apple framework leakage into `VRemindCore`:** Zero `AppKit`, `SwiftUI`, `Combine`, `UserNotifications`, `ServiceManagement`, or `WidgetKit` imports in `VRemindCore`.
- **Requiring API keys or external dependencies:** Both `VRemindCore` and `VRemindKit` remain zero-dependency Swift packages that work out of the box with no API keys.
- **Breaking Command Line Tools builds:** `scripts/build-app.sh` and `scripts/test.sh` must continue to build universal macOS 12+ (`arm64` + `x86_64`) binaries and run all Swift Testing suites using only Xcode Command Line Tools (no full Xcode IDE).

## 3. Constraints

- **Deployment Target:** macOS 12.0+ (`.macOS(.v12)`), Universal (`arm64` + `x86_64`), Swift 5.9+.
- **Portability Boundary:** `VRemindCore` must compile cleanly using only `Foundation` (and `FoundationNetworking` under `#if canImport(FoundationNetworking)`) so it has no Apple-SDK coupling. Avoid macOS-only APIs like `autoreleasepool` in `VRemindCore` (guard with `#if canImport(ObjectiveC)` if used, or omit in pure Swift).
- **Dependencies:** Zero third-party SwiftPM dependencies.
- **Concurrency & Power:** Preserve bounded concurrency of `3` concurrent channel fetches per batch and automatic display sleep/wake pause/resume on macOS.
- **Rate Limits & Ephemeral Networking:** Continue using cache-free ephemeral `URLSession` requests with no persistent HTTP cache.

## 4. Approaches Considered & Trade-Offs

### Approach 1: Pure `VRemindCore` SwiftPM Target + `VRemindKit` Mac Bridge *(Chosen)*
- **Description:** Split `Package.swift` into `VRemindCore` (`Foundation`-only) and `VRemindKit` (macOS bridge depending on `VRemindCore`). Extract `StreamProvider`, `YouTubeStreamProvider`, `TwitchStreamProvider`, `StreamMonitorEngine`, domain models, celebration detection, and persistence protocols into `VRemindCore`. Keep `ObservableObject` stores, `NSWorkspace` hooks, `UserNotifications`, `WidgetSnapshotStore`, and SwiftUI views in `VRemindKit`.
- **Pros:** Compiler-enforced boundary prevents Apple framework leaks; `VRemindCore` compiles on non-Apple Swift toolchains as-is or serves as a clean blueprint for Qt/GJS ports; keeps the Mac repo lightweight with zero extra CLI binaries to maintain.
- **Cons:** Non-Swift ports (e.g., pure Qt/C++ or GJS) still either embed/wrap `VRemindCore` or translate its clean modules rather than invoking a pre-built CLI binary.
- **Decision:** Chosen by the project author because it directly realizes the `VRemind` → `VRemindKit` (Mac bridge) → `VRemindCore` (portable engine) vision while keeping the Mac repo focused and native.

### Approach 2: `VRemindCore` + Headless `vremind-cli` JSON Runner
- **Description:** Same `VRemindCore` split, plus a cross-platform CLI executable printing JSON statuses to stdout for KDE/GNOME extensions to shell out to.
- **Pros:** Lets non-Swift desktop extensions consume scraping directly via subprocess calls.
- **Cons:** Requires Linux users to install/build Swift, introduces an extra CLI/JSON contract to version and test in the Mac repo.
- **Decision:** Rejected for 1.3 to keep scope focused on the Mac app and `VRemindCore` library boundary.

### Approach 3: Single `VRemindKit` Target with Internal Protocols
- **Description:** Keep one library target in `Package.swift` and organize YouTube/Twitch behind internal protocols.
- **Pros:** Minimal file churn.
- **Cons:** Does not enforce Apple-framework isolation (`AppKit`/`Combine` can creep back in) and does not produce a standalone `VRemindCore` module.
- **Decision:** Rejected because it misses the "Better Together" backend separation goal.

## 5. Detailed Architecture & Component Design

### 5.1 Package Target Topology (`Package.swift`)
```text
VRemind (executable: macOS AppKit entry & window controllers)
   └── depends on VRemindKit
VRemindWidget (executable: macOS WidgetKit extension)
   └── depends on VRemindKit
VRemindKit (library: Mac bridge — SwiftUI, AppKit, Combine, UserNotifications, WidgetKit)
   └── depends on VRemindCore (@_exported import VRemindCore)
VRemindCore (library: Pure Foundation + FoundationNetworking — portable business engine)
   └── zero external dependencies, zero Apple UI/system frameworks

Tests:
- VRemindCoreTests (tests VRemindCore directly, Foundation-only)
- VRemindKitTests (tests VRemindKit Mac bridge, stores, notifications, views, widgets)
```

> **Builder Call:** `VRemindKit` will use `@_exported import VRemindCore` so existing Mac views/controllers and `VRemindWidget` continue accessing shared models seamlessly while keeping `VRemindCore` strictly isolated.

### 5.2 `VRemindCore` Components

#### 1. `StreamPlatform` (`Sources/VRemindCore/Models/StreamPlatform.swift`)
```swift
public enum StreamPlatform: String, Codable, CaseIterable, Sendable, Hashable {
    case youtube
    case twitch

    public var displayName: String { ... } // "YouTube", "Twitch"
}
```
- Designed as a `String`-backed `Codable` enum so `.kick` or `.rss` can be added in future versions without breaking existing records.

#### 2. `WatchedChannel` (`Sources/VRemindCore/Models/WatchedChannel.swift`)
- Fields:
  - `public let id: String` — canonical key `"\(platform.rawValue):\(handle.lowercased())"` (e.g. `"youtube:@bukancaitlyn"`, `"twitch:ironmouse"`).
  - `public let platform: StreamPlatform`
  - `public var name: String`
  - `public let handle: String` — platform-normalized handle (`"@bukancaitlyn"` for YouTube; `"ironmouse"` lowercase login for Twitch).
  - `public var avatarURL: URL?`
  - `public var lastNotifiedVideoId: String?` (kept property name or migrated via `CodingKeys` for backward-compatible JSON decoding of 1.2 data; see migration below).
  - `public var lastNotifiedUpcomingId: String?`
  - `public var lastStreamedAt: Date?`
- **1.2 Backward-Compatible Decoding:**
  - Custom `init(from decoder:)` reads `platform` via `decodeIfPresent(StreamPlatform.self, forKey: .platform) ?? .youtube`.
  - If `id` does not already have a `"<platform>:"` prefix (i.e. legacy 1.2 entry like `"@bukancaitlyn"`), normalize `id` to `Self.makeID(platform: platform, handle: handle)` on decode (or via `ChannelStore` migration).
  - Preserve `WatchedChannel.normalizeHandle(_:)` as a convenience delegating to `.youtube` (so existing unit tests/callers keep working cleanly) alongside `WatchedChannel.normalizeHandle(_:for:)`.
- **Platform Handle Normalization Rules:**
  - **YouTube (`.youtube`):** Existing rules (`@handle`, `youtube.com/@handle`, `youtu.be/@handle`, or bare `handle` -> `@handle`; allowed chars `[A-Za-z0-9_.-]`).
  - **Twitch (`.twitch`):** Accepts `username`, `@username` (strips leading `@`), or `twitch.tv/<username>` / `www.twitch.tv/<username>` / `m.twitch.tv/<username>` (with or without `https://`, ignoring trailing `/` or `?query` / `#fragment`). Validates Twitch login rules (`[A-Za-z0-9_]`, 1–25 characters) and normalizes to lowercase (e.g. `"ironmouse"`).
  - **URL-based Platform Detection (`detectPlatformAndHandle(from:)`):** Helper that inspects an explicit URL (`youtube.com`/`youtu.be` vs `twitch.tv`) so if a user pastes a full channel URL into the input bar, the UI can auto-select the matching platform in the dropdown.

#### 3. `StreamStatus` (`Sources/VRemindCore/Models/StreamStatus.swift`)
```swift
public enum StreamStatus: Codable, Equatable, Sendable {
    case live(videoId: String, title: String, startedAt: Date?)
    case upcoming(videoId: String, title: String, scheduledStartTime: Date?)
    case offline(lastStreamedAt: Date?)
    case unknown
}
```
> **Builder Call:** Keep the `.live(videoId:title:startedAt:)` and `.upcoming(videoId:title:scheduledStartTime:)` case names and associated value labels intact for 1.3 (`videoId` holds the platform's stream identifier—YouTube video ID or Twitch stream ID) to minimize churn across existing `VRemindKit` views and tests, while deriving platform-appropriate URLs via `StreamProvider` / `LinkOpener`.

#### 4. `StreamProvider` Protocol & Registry (`Sources/VRemindCore/Providers/`)
```swift
public typealias HTTPFetcher = @Sendable (URLRequest) async throws -> (Data, URLResponse)

public struct ChannelFetchResult: Equatable, Sendable {
    public let pageResult: LivePageResult
    public let channelTitle: String?
    public let avatarURL: URL?
}

public protocol StreamProvider: Sendable {
    var platform: StreamPlatform { get }
    func normalizeHandle(_ input: String) -> String?
    func channelURL(for handle: String) -> URL?
    func watchURL(for channel: WatchedChannel, status: StreamStatus) -> URL?
    func fetchChannelState(for channel: WatchedChannel, fetcher: HTTPFetcher) async throws -> ChannelFetchResult
}
```
- **`StreamProviderRegistry`:** Maps `StreamPlatform` -> `any StreamProvider` (default registry includes `YouTubeStreamProvider` and `TwitchStreamProvider`, and supports injecting mock providers in tests).
- **`YouTubeStreamProvider`:**
  - Uses `LivePageParser` (moved into `VRemindCore`) to parse `https://www.youtube.com/@<handle>/live`.
  - `watchURL`: `https://www.youtube.com/watch?v=<videoId>` when `.live`/`.upcoming` with non-empty `videoId`, otherwise `https://www.youtube.com/@<handle>/live`.
- **`TwitchStreamProvider` (Key-Free):**
  - Uses Twitch's public unauthenticated web GraphQL endpoint (`https://gql.twitch.tv/gql`) with Twitch's public web `Client-ID` header (`kimne78kx3ncx6brgo4mv6wki5h1ko`)—requiring zero user API keys or OAuth setup.
  - Queries `user(login: "<handle>")` for:
    - `id`, `login`, `displayName`
    - `profileImageURL(width: 300)`
    - `stream { id title createdAt type }`
  - Maps response via a pure, unit-testable `TwitchResponseParser`:
    - `user == nil` → `.unrecognized` (or `.notLive(nil, nil)` if transient; wait: if `errors` present or HTTP non-2xx → throw/unrecognized; if `user == nil` → `.unrecognized` so nonexistent channels show offline/unknown without crashing).
    - `user.stream != nil` (and `type == "live"` or non-empty `id`) → `.live(videoId: stream.id, title: stream.title, startedAt: iso8601Date(stream.createdAt))`.
    - `user.stream == nil` → `.notLive(channelTitle: user.displayName, avatarURL: profileImageURL)`.
  - `channelURL` & `watchURL`: `https://www.twitch.tv/<handle>`.

> **Builder Call:** If Twitch's `gql.twitch.tv/gql` ever returns a non-2xx status or malformed payload during a poll, `TwitchStreamProvider` reports failure / `.unrecognized` (mapped to `.unknown` status, never overwriting valid cached `name` or `avatarURL`), matching YouTube's behavior.

#### 5. `StreamMonitorEngine` (`Sources/VRemindCore/Services/StreamMonitorEngine.swift`)
Pure `Foundation` monitoring coordinator (replaces the business/polling logic previously inside `VRemindKit.StreamMonitorService`):
- Bounded batch concurrency of `3` channels per batch.
- Uses `StreamProviderRegistry` to dispatch each `WatchedChannel` to its platform provider.
- Evaluates notification decisions (`shouldNotifyLive`, `shouldNotifyUpcoming`) using `ChannelStoreProtocol` / snapshot state + `AppSettings`, returning/emitting structured `MonitorEvent`s (`.statusUpdated`, `.notifyLive`, `.notifyUpcoming`, `.notifyDeveloperBirthday`, `.refreshCompleted`) via an injected handler/closure or callback delegate—without importing `AppKit`, `Combine`, or `UserNotifications`.
- Includes pure `ChannelStateHelpers` for sorting/splitting sections (`live`, `upcoming`, `offline`) and `SecretCheck` / `CelebrationDetector` / `ElapsedTime` / `SemanticVersion` / `AppConstants`.

#### 6. Persistence & Settings Contracts in `VRemindCore`
- Move `AppSettings` (pure `Codable` struct) and `GitHubRelease` into `VRemindCore`.
- Define lightweight protocols (`ChannelStorage`, `SettingsStorage`) so `VRemindKit` implements them with `UserDefaults` on macOS, while non-Apple ports can plug in JSON files (`JSONFileChannelStorage` optional helper in `VRemindCore` using `FileManager` + `Codable`, 100% pure `Foundation`) or SQLite/GSettings/KConfig.

### 5.3 `VRemindKit` Mac Bridge Updates

#### 1. Stores & Services
- **`ChannelStore` (`UserDefaults`):**
  - Migrates legacy 1.2 channels on load (`platform` defaults to `.youtube`, `id` normalized to `"youtube:@handle"` if missing prefix, saving migrated payload back to `UserDefaults`).
  - `addChannel(platform: StreamPlatform = .youtube, handle: String, name: String? = nil, avatarURL: URL? = nil)`: normalizes via `StreamProviderRegistry` / `WatchedChannel.normalizeHandle(_:for:)`, deduplicates by `id` (`platform` + lowercased handle), and persists.
  - Default starter channel remains Caitlyn Momochi (`platform: .youtube`, `handle: "@bukancaitlyn"`).
- **`StreamMonitorService` (`@MainActor ObservableObject`):**
  - Wraps `StreamMonitorEngine`, bridges `NSWorkspace.screensDidSleepNotification` / `screensDidWakeNotification` to pause/resume polling, updates `@Published statuses`, forwards notification events to `NotificationService`, and exports `WidgetSnapshot` via `WidgetSnapshotStore`.
  - Adapts `StreamMonitorService.Fetcher` (`(URL) async throws -> (Data, URLResponse)`) and `HTTPFetcher` (`(URLRequest) async throws -> (Data, URLResponse)`) cleanly so existing test mocks continue to work or upgrade easily.
- **`NotificationService`:**
  - `notifyLive` / `notifyUpcoming` accept `platform: StreamPlatform` (default `.youtube`) and `watchURL: URL?` (stored in `userInfo["watchURL"]` alongside `videoId` and `platform`).
  - `handleNotificationClick(userInfo:)` opens `watchURL` if valid `http`/`https`, falling back to `LinkOpener.videoURL(for: videoId)` for backward compatibility with pending 1.2 notifications.
- **`LinkOpener`:**
  - Adds platform-aware `streamURL(for channel: WatchedChannel, status: StreamStatus) -> URL` and `channelURL(for platform: StreamPlatform, handle: String) -> URL`, delegating to `StreamProviderRegistry` in `VRemindCore`.

#### 2. WidgetKit Bridge (`WidgetSnapshot`, `WidgetSnapshotStore`, Widget Views)
- **`WidgetChannelItem`:**
  - Add `public let platform: StreamPlatform` (default `.youtube`; `Codable` decodes missing `platform` as `.youtube` for backward compatibility with cached `widget-cache.json`).
  - Update `id` to `"\(platform.rawValue):\(handle.lowercased())"` so a creator tracked on both YouTube and Twitch appears uniquely in `ForEach` and doesn't collide.
  - Update `WidgetSnapshotStore.avatarFilename(for:platform:)` to `"\(platform.rawValue)_\(safeHandle).jpg"` (preserving `avatarFilename(for:)` convenience for YouTube) so avatars for the same handle across platforms never overwrite each other.
  - Update `WidgetChannelItem.channelURL` and `videoURL` / `streamURL` to resolve Twitch (`https://www.twitch.tv/<handle>`) as well as YouTube.
- **Widget Views (`MediumWatchlistWidgetView`, `LargeDashboardWidgetView`):**
  - Update empty-state copy from `"Add YouTube channels..."` to `"Add channels in VRemind menu bar"` / `"Add YouTube or Twitch channels..."`.
  - Display the same small platform badge dot on channel avatars in `MediumWatchlistWidgetView` and `LargeDashboardWidgetView` where circular avatars appear.

#### 3. Menu Bar & Onboarding UI (Matching User Mockup)
- **`ChannelAvatarView` / `ChannelRowView`:**
  - Add an optional `platform: StreamPlatform?` parameter to `ChannelAvatarView` (or a small `PlatformBadgeView` overlay in `ChannelRowView` and widget avatar thumbnails).
  - Badge placement & styling (per user's mockup):
    - Small solid colored circle (~10–11pt diameter) pinned to `.bottomTrailing` of the 36×36 circular avatar with a subtle 1.5pt dark/background border ring so it pops cleanly against both light and dark avatars.
    - Colors defined in `Theme.swift`:
      - YouTube: red (`Color.red` / `#FF0000`)
      - Twitch: purple (`Color(red: 0.569, green: 0.275, blue: 1.0)` / `#9146FF`)
  - `ChannelRowView`:
    - Displays `channel.name` and formatted handle (`@bukancaitlyn` for YouTube, `ironmouse` or `@ironmouse` — **Builder Call:** display `channel.handle` directly so YouTube shows `@bukancaitlyn` and Twitch shows `ironmouse`, matching each platform's convention; tooltip shows `"\(platform.displayName): \(channel.handle)"`).
    - `streamURL` uses `LinkOpener.streamURL(for: channel, status: status)` so clicking a Twitch row opens `https://www.twitch.tv/<handle>`.
    - `CelebrationDetector.detect(status:channel:date:)` continues checking stream titles on both YouTube and Twitch (and restricts the Dec 31 developer birthday easter egg to Caitlyn Momochi).
- **`AddChannelBarView` & `MenuBarStatusViewModel`:**
  - Add `@Published public var selectedPlatform: StreamPlatform = .youtube` to `MenuBarStatusViewModel`.
  - On the left side of the text field in `AddChannelBarView`, place a compact platform dropdown (`Picker` / `Menu`) showing the selected platform icon/dot + short label (or compact pill with chevron) allowing selection between **YouTube** and **Twitch**.
  - Dynamic placeholder text:
    - YouTube selected: `"Add YouTube @handle..."`
    - Twitch selected: `"Add Twitch username..."`
  - Smart URL auto-detection: If the user pastes a full `twitch.tv/...` URL while YouTube is selected (or `youtube.com/...` / `youtu.be/...` while Twitch is selected), `addChannel()` auto-detects the platform from the URL and normalizes accordingly.
  - Validation error message adapts to the selected platform (e.g. `"Please enter a valid channel handle or URL"`).
- **`OnboardingView` & `OnboardingViewModel`:**
  - Add `selectedPlatform: StreamPlatform = .youtube` with a compact platform picker alongside the starter handle field, and update helper copy from `"Enter a YouTube handle starting with @ (defaults to @bukancaitlyn)."` to `"Enter a YouTube @handle or Twitch username (defaults to @bukancaitlyn on YouTube)."`
- **`MenuBarStatusView`:**
  - Update empty-state copy from `"Add a YouTube handle below to track live streams."` to `"Add a YouTube or Twitch channel below to track live streams."`
